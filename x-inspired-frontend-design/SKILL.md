# X-Inspired Frontend Design

Use flat surfaces, crisp type, fine separators, and one restrained accent. Keep the product's own identity, existing design system, and requested scope. Choose structure by task. A table fits comparison, a narrow column fits reading, and a grid fits browsing. Add social patterns only where the product calls for them.

- Make the main action easy to find. Use cards and panels where they group related work. Favor compact rows in workspaces and give reading and onboarding more room.
- Start with the project's tokens and theme. If needed, use near-white or near-black surfaces, a system sans-serif, and a muted secondary text color that still meets contrast requirements. Treat `#1D9BF0` as a starting accent and verify the actual text and control contrast. Support the themes the project calls for.
- Choose breakpoints where content stops fitting. Let labels wrap and preserve essential actions at narrow widths. Give a wide comparison table its own accessible scroll area when it needs one.
- Keep labels and feedback short and specific. Use familiar units, visible keyboard focus, and native controls where they fit. Make loading, missing data, and failure distinguishable when they affect the task. Test the main journey and changed interactions at representative widths, including keyboard and relevant theme or motion settings.
