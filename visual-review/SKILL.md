# Visual Review

Inspect the rendered interface yourself. Keep tracked content read-only and save browser artifacts in a temporary directory. Use the available browser tooling. Ask for user annotations only when requested or when a material ambiguity prevents progress.

Confirm the intended build is running. Exercise the affected journey at representative widths and inspect states that could change the verdict. Check keyboard behavior for changed interactions, and include other themes or browsers when the change affects them. Capture screenshots when they help explain a finding.

Lead with `APPROVED` if the inspected behavior has no material issue, `CHANGES_REQUIRED` for a material visual or interaction defect, or `BLOCKED` when the evidence needed for a verdict is unavailable. Gate delivery only when required by the user or workflow. Give the element, state or viewport, observed impact, and concrete correction. State what you inspected and any material gaps.
